# 起始版本观测记录

这些记录由作者在 Linux/WSL 上对起始工程实际运行故障注入采集，使用本地 CPU 后端，
不是生产事故日志。JSON 中标记了采集所用的起始提交；请求、消息、状态和计数均为
该次运行的实际值。请求 ID 是运行时生成的，重现实验时无需复用。

- `session-01.json`：单个流式请求。记录后端收到的 Work、依次送达的 WorkerEvent、
  客户端收集到的事件、最终 status 和监控计数。没有连接外部模型。
- `session-02.json`：同一个磁盘 journal 被两个先后运行的进程打开。第一个进程的
  后端交付一个 token 后保持等待；客户端读到该 delta 后进程直接退出，未执行 close。
  第二个进程启动后提交完全相同的请求，记录返回值、状态、journal 事件和监控计数。
  宿主及文件系统始终运行。退出方法和退出码随记录提供。

单个 `events` 数组按客户端或 journal 返回顺序保留。session-01 中先收集流，再记录
整个数组，因此顶层数组顺序不是客户端与后端之间的精细时间线。指标只保留实际
计数器和资源 gauge，未收录受本机运行耗时影响的 TTFT 行。

记录反映起始工程的行为，不代表修复后的正确答案，也不是完整的验收场景清单。
请依据公开契约判断现象的含义，自行构造复现、检查源码并验证修复。
这些材料没有给出根因、应修改的函数、内部数据结构或补丁。
