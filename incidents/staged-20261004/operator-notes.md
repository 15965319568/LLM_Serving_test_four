# 放量演练原始材料

本目录是独立的合成演练，以实验时钟记录接纳时间，不能与另一个事故目录混导。
initial.json是第一次收集批次；late-batch.json为稍后收到的质量重评，文件接收顺序与
event的update_seq并不相同。worker日志记录的是工作进程视角，不能直接代表接纳归属。

当班记录（未核实）：

- 计划从20%开始，后续按production profile推进。观察区间为[100,150)、[150,200)、[300,350)、[350,400)。
- 一名操作者换了assessment ID后又提交了[100,150)，界面显示的计数让人困惑。
- 另一轮在第一个窗口应用后导入了late-batch.json，再评估第二个窗口；旧看板仍显示首窗口健康。
- 某次边缘路由已更新，控制端在收到ACK前退出；值班人员用同一个operation重试。
- 历史exporter、流式edge与quality的单位和完成时间不同，不能按文件行序把记录覆盖掉。

可按README的独立state流程选择initial.json导入。要精确重放实验时钟和ACK边界，可使用
公开的ManualClock与Fleet Python API；真实系统时间的CLI不应把300秒误认为当前阶段刚生效。
材料用于诊断，不限制测试使用的发布ID、时间、策略、版本或步骤数量。
